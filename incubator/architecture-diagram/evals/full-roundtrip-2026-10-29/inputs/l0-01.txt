Dynamic diagram (deployment view): Token-based API authorization.
Requirement: Authenticate users and authorize each API request.

A User [Person] signs in through a Web sign-in page [Container: Web app] with a username and password. Both the User and Web sign-in page are outside AWS Cloud. The page collects and submits the credentials to Amazon Cognito user pool over HTTPS; the page does not verify the password. Cognito verifies the password, authenticates the user and issues tokens. The ID token carries user attributes, for example cognito:username = alex; custom:tenantId = T-001; custom:type = Customer; cognito:groups = [Customers].

AWS Cloud [Deployment node] encloses Amazon Cognito user pool [Container: Amazon Cognito], Amazon Verified Permissions [Container: AWS managed service], Backend APIs [Container: REST API], and API enforcement [Software system boundary]. API enforcement encloses only Amazon API Gateway [Container: AWS managed service] and Lambda authorizer [Container: AWS Lambda]. API Gateway enforces the authorization result; Lambda authorizer verifies the token and queries policy; Amazon Verified Permissions makes policy decisions.

The Web sign-in page sends the token with each API request to Amazon API Gateway over HTTPS. API Gateway passes the token to the Lambda authorizer using a generic AWS invocation. The authorizer verifies the token and asks the Amazon Verified Permissions decision endpoint over HTTPS whether the request is allowed. If allowed, API Gateway forwards the request to Backend APIs over HTTPS. If authorization fails, API Gateway returns HTTP 403 with an authorization error message to the Web sign-in page over HTTPS.

Represent the main sequence as 1. Authenticate (returns tokens); 2. API request with token; 3. Pass token for authorization; 4. Query policy; 5. Forward allowed request. A separate bold 5' relationship represents the HTTP 403 failure response. Policy query is auxiliary and dashed; main calls are solid. Arrows point from caller to callee; return tokens are folded into the authentication label, rather than a second return arrow. User uses the Web sign-in page. Show the token example in a local comment near Step 1 and explain the notation in a legend. All calls remain inside shared enclosing domains and cross only required boundaries.
