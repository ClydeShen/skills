Dynamic diagram (deployment view): Private cross-cloud API access from Azure to AWS.
Requirement: Azure integration workloads privately call internal AWS API Gateway REST APIs. DNS resolution and API traffic are distinct flows, labeled A and B.

Azure Cloud contains three spoke VNets, one each for dev, test and prod. Callers are Azure Function Apps or Logic Apps in those spokes. Show a representative Function App with the Logic Apps alternative and all three environments stated; this does not mean three extra application flows. Spokes connect to a hub VNet containing Azure Firewall and Azure VPN Gateway, and to a separate DNS extension VNet containing Azure DNS Private Resolver inbound and outbound endpoints. The outbound endpoint has a DNS forwarding ruleset for *.execute-api.{region}.amazonaws.com targeting the IP addresses of the AWS Route 53 Resolver inbound endpoint.

An IPsec site-to-site VPN joins Azure VPN Gateway to AWS Site-to-Site VPN attached to AWS Transit Gateway. Draw the VPN connection explicitly between the clouds. AWS Cloud and a Region contain a network services account and three workload accounts, one per environment (dev, test, prod). Transit Gateway is an infrastructure node in the network services account, attached to three VPCs: ingress VPC 10.1.0.0/20, inspection VPC 10.2.0.0/24, and egress VPC 10.3.0.0/20. Ingress contains Route 53 Resolver inbound endpoint and the private hosted zone execute-api.{region}.amazonaws.com, associated with the ingress VPC, not attached to the resolver endpoint. Inspection contains AWS Network Firewall performing IDPS. Egress contains an execute-api interface VPC endpoint. Each workload account contains a private API Gateway REST API protected by a resource policy and backed by Lambda; Lambda runtime remains unspecified, so use AWS Lambda as its technology. The VPC endpoint is the private entry to the API Gateway APIs.

Flow A, DNS: the representative Azure caller queries the Private Resolver inbound endpoint. Private Resolver uses its outbound endpoint/ruleset to forward the execute-api query toward the Route 53 inbound endpoint over DNS port 53. The stated traffic path traverses Azure Firewall, Azure VPN Gateway, the IPsec VPN, Transit Gateway and AWS Network Firewall before reaching the ingress resolver. The resolver uses the private hosted zone and returns the execute-api interface endpoint's private IP; fold that response into the query label. Describe traffic-forwarding legs as DNS routing, not software calls initiated by the transit devices. DNS queries also pass AWS Network Firewall in this synthetic fixture. The Transit Gateway/VPC routing details beyond that specified forwarding path are not given; do not invent route tables.

Flow B, API call: the Azure caller sends HTTPS port 443 traffic through Azure Firewall and Azure VPN Gateway, across the IPsec VPN to Transit Gateway, through Network Firewall inspection and toward the execute-api interface endpoint. The endpoint provides access to the private API Gateway in the corresponding workload account, subject to its resource policy; API Gateway invokes Lambda. Route 53 Resolver outbound endpoints do not forward HTTPS requests and no Route 53 outbound endpoint is retained in this fixture. Preserve the distinct roles of DNS and application routing.
