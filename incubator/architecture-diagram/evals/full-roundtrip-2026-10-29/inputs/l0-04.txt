Dynamic diagram (deployment view): AWS document metadata sync and Azure on-demand retrieval.
Requirement: Cosmos DB in Azure decouples document discovery from AWS availability. If cross-cloud connectivity fails, metadata-based requests such as finding documents can still be served. The described live S3 retrieval path still depends on access to S3.

AWS Cloud contains a Document publishing service [Software system] as a truthful generic plain box, Amazon S3 as the document store, and Amazon SQS queues (x3: documents, templates, bundles). The producer's actual product/name is unknown; do not invent one. Azure Cloud contains Cosmos DB (NoSQL document metadata store), Azure Blob Storage (temporary document storage with a retention policy; no duration specified), and an Outbound workflows software system boundary. That boundary contains SQS listener workflows (x3), a Processing workflow and a Retrieving workflow, all Azure Logic Apps. The three listeners correspond to SQS-Document-Cosmos, SQS-Template-Cosmos and SQS-Bundle-Cosmos, one per record type/queue.

Network resolution for this synthetic fixture: use public HTTPS service endpoints between Azure and S3/SQS, not an assumed private connection or VPN. S3 requests use AWS Signature authentication. The exact producer identity, cloud region and retention duration are unspecified.

Flow A, write/metadata sync: when a document is published or a template version approved, the publishing service saves the document in S3 and publishes a metadata event asynchronously to the appropriate SQS queue. There is one queue per record type, not one combined queue. Azure's corresponding SQS listener polls SQS for messages using the SQS API over HTTPS; arrows point from listener to queue because the listener initiates polling, with returned events in the label. Each listener inserts or updates metadata in Cosmos DB by the record's identity. Preserve the three queue/listener types and the distinction between document content in S3 and metadata in Cosmos DB. Show A1 producer->S3 Save document [HTTPS], A2 producer->SQS Publish metadata event [async, SQS], A3 listener->SQS Poll [SQS API/HTTPS], returns events, and A4 listener->Cosmos DB Upsert metadata by record ID.

Flow B, read/retrieval: Processing workflow queries Cosmos DB for metadata and gets the S3 reference. It passes that reference to Retrieving workflow. Retrieving workflow gets the document from S3 over HTTPS using AWS Signature, saves it once to temporary Azure Blob Storage under its retention policy, and returns the blob reference to Processing workflow.
