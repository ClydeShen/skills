## Scope and source fidelity

The heavy path follows customers through Cloudflare at `help.example.com`, the Application Load Balancer, and the LangGraph assistant. The AWS region is `us-east-1`; both the assistant and MCP server are nested in the EKS cluster. Bedrock sits in the region outside the cluster. Pinecone, Salesforce, OpenAI, GitHub, Langfuse Cloud, and Grafana Cloud remain outside the AWS boundary.

The numbered calls preserve the source order: retrieve help articles, ask Anthropic Claude through Amazon Bedrock to write the answer, then obtain open cases through MCP and Salesforce. Numbers denote sequence, not broadcast. Normal responses are folded into the initiating arrows. No failures are specified, so none are invented.

GitHub Actions calls OpenAI for changed-article embeddings and writes those embeddings to the same Pinecone index queried by the assistant. A separate management connector labeled Terraform originates from that same workflow and targets the AWS region as a resource scope. Runtime tracing connects the assistant to Langfuse Cloud; metrics originate at the EKS boundary and go to Grafana Cloud. Dashed lines denote ingestion, management, and telemetry.

No business rules, schemas, sample data, or unrelated alerting were supplied or omitted.
