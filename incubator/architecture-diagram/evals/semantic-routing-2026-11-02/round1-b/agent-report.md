# Document Q&A on Azure — companion account

Created [diagram.drawio](diagram.drawio) from [scenario.md](scenario.md), using the architecture-diagram skill and draw.io v32.6.1 XML. All symbols, labels, groups and connectors are editable.

## Scope and source fidelity

The view includes employee sign-in, chat, passage search, answer generation, conversation storage, policy uploads, document splitting, embedding generation and index writes. It also includes the stated secrets, telemetry and deployment relationships. No scenario content was excluded.

Q1–Q3 identify the web app's sequential calls: retrieve passages, send the question and retrieved passages to Azure OpenAI for an answer, then save the conversation. They are ordered calls from the app, not parallel broadcasts or direct calls between the three dependencies. Normal responses are folded into request arrows.

The lower lane shows staff uploading policies to Blob Storage, each upload triggering the Function, and the Function splitting documents, generating embeddings (I1) and writing them to AI Search (I2). The same OpenAI resource and Search index serve both flows. The OpenAI symbol represents the shared resource, not a claim that a single model deployment performs both generation and embedding.

The light Application components group is a logical grouping of the web app and Function. Its deployment, secrets and telemetry connectors apply to both members; it is not a network, resource group, security boundary or shared hosting plan. Only the web app is nested in the dashed westeurope region. Other services' positions outside that outline indicate unspecified location, not a claim that they are deployed outside westeurope. Entra ID is not placed inside a region.

## Assumptions and unresolved details

- Employee-to-chat access is the natural interpretation of using the web app. Sign-in is shown independently; token format, redirect sequence, validation and authorization policies are unspecified.
- Employees and staff are roles, not a claim that they are disjoint populations. The upload interface, upload authentication and whether uploads pass through the web app are unspecified; the upload arrow expresses the stated destination only.
- Blob-to-Function expresses the stated upload trigger. No Event Grid, queue, polling mechanism, delivery guarantee or retry policy is asserted.
- Model names, generation and embedding deployments, vector dimensions, retrieval mode, indexing schema and timing are unspecified. The function's embedding results and the web app's passage results return along their respective call relationships.
- Subscription, resource group, remaining service regions, protocols, endpoints, public/private exposure, VNet integration, identities and permission grants are unspecified. No such infrastructure was added.
- There are no explicit failure or denial paths in the source, so none are invented. Ingestion completion and search visibility are not asserted to be immediate.

## Engineering review and design risks

Entry is visible at employees and staff. Only the App Service location is established: an outage affecting that deployment could interrupt chat. The source gives no zone distribution, replicas, failover or recovery objectives, so availability and true single points of failure cannot be established. Each service symbol denotes one source-level service/resource, not a measured replica count.

The shared OpenAI resource and Search index couple ingestion and question answering: contention, quotas or service failure could affect both paths. Document access filtering and conversation retention are unspecified; confirm those policies before treating this as an implementation design. These are review concerns, not added components or established deployment defects.

The only deployment outline is the known web app region. App calls cross it to dependencies whose locations are unspecified. The logical application group carries shared operations relationships; runtime ingestion, embedding and query connectors cross it only when their endpoints require that. No connector implies an unstated network transit service.
