# Companion account

Created `diagram.drawio` from `scenario.md` as a single editable architecture overview, targeting draw.io 32.6.1. Eleven vendor icons are embedded for offline display; AWS shapes use the native draw.io library.

## Scope and source fidelity

The customer path is Customers, Cloudflare at `help.example.com`, the Application Load Balancer, and the LangGraph assistant. The AWS region contains the load balancer and EKS; both the assistant and MCP server are nested in EKS. Numbered calls preserve the scenario's stated order: retrieve Pinecone articles, generate with Anthropic Claude through Amazon Bedrock, then look up open cases through MCP and Salesforce. Normal responses are folded into their request arrows.

The upper light-filled band groups publishing and provisioning activities. It is a logical group, not a deployment or security boundary: OpenAI remains an external API. GitHub supplies changed articles to GitHub Actions, which calls the embeddings API and writes the Pinecone index. Terraform's caption records that it runs in the same workflow; its management arrow ends at the AWS region rather than inventing per-resource management details. Separate dashed paths show agent-run traces to Langfuse Cloud and cluster metrics to Grafana Cloud. The metrics arrow starts at EKS because the source names no collector.

All stated systems and relationships are retained. No business rules, schemas, sample data, struck-out content or unrelated alerting were present to exclude.

## Assumptions and unresolved details

- EKS is placed with the ALB in `us-east-1`, following the scenario's AWS deployment context. Bedrock is also placed there for this overview; its actual endpoint region is unspecified. Cross-region inference is not established by the source.
- Cloudflare is shown as the application proxy, without adding DNS, WAF or caching behavior.
- The article-change link indicates the supplied workflow input; the exact GitHub event and filters are unspecified. The source does not establish whether Terraform runs before, after or concurrently with indexing.
- No VPCs, subnets, availability zones, pod counts, public/private exposure, transport protocols, credentials, authentication, egress components, model versions or failure responses are invented.
- The scenario does not explain query embedding, how article text reaches the embedding call, or how embeddings are returned and combined with records. These details are folded into the stated Actions and retrieval interactions rather than expanded into additional infrastructure.

## Engineering review and design risks

Traffic entry is visible from the customer through the proxy to AWS. The diagram shows one described region; a regional outage could interrupt the depicted request path. Zone placement, replicas, failover and availability guarantees are unspecified, so one service symbol does not claim one running instance. Pinecone, Bedrock, Salesforce and Cloudflare are dependencies whose failures could affect support responses; retries and degraded modes are not described.

Connectors cross the AWS and EKS boundaries only to reach their stated dependencies. Telemetry exits those boundaries, and management enters AWS at regional scope. No deployment corrections or recommended infrastructure were added. Source fidelity does not validate production security, capacity or resilience.
