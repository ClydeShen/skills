TITLE AND PURPOSE
Title: Dynamic diagram (deployment view): Private cross-cloud API access from Azure to AWS.
Subtitle: Azure integration workloads privately call internal AWS API Gateway REST APIs. Flow A resolves DNS; flow B carries the corresponding environment's API request.

BOUNDARIES, MEMBERSHIP, AND RESPONSIBILITIES
Azure Cloud is a deployment node containing five deployment nodes: dev spoke VNet — representative, test spoke VNet, prod spoke VNet, DNS extension VNet, and Hub VNet.
Each spoke contains a Representative integration caller, labeled Logic Apps alternative and [Container: Azure Function Apps]. The test and prod callers also say Same A/B path. Only the dev representative has explicitly drawn outgoing paths.
DNS extension VNet contains Private Resolver inbound endpoint and Private Resolver outbound endpoint. Each is an infrastructure node of Azure DNS Private Resolver.
Hub VNet contains Azure Firewall [Infrastructure node: Azure Firewall] and Azure VPN Gateway [Infrastructure node: Azure VPN Gateway].

AWS Cloud is a deployment node containing Region: {region}, also a deployment node. That region contains Network services account and dev, test, and prod workload accounts, all labeled deployment nodes.
Network services account contains Site-to-Site VPN attachment [Infrastructure node: AWS Site-to-Site VPN], Transit Gateway with VPC routing details: unspecified [Infrastructure node: AWS Transit Gateway], and three deployment-node VPC boundaries.
Ingress VPC — 10.1.0.0/20 contains Route 53 inbound endpoint, labeled DNS only [Infrastructure node: Amazon Route 53 Resolver], and Private hosted zone execute-api.{region}.amazonaws.com, labeled Associated with ingress VPC [Infrastructure node: Amazon Route 53].
Inspection VPC — 10.2.0.0/24 contains AWS Network Firewall — IDPS [Infrastructure node: AWS Network Firewall].
Egress VPC — 10.3.0.0/20 contains execute-api interface VPC endpoint, labeled Private API entry [Infrastructure node: AWS VPC endpoint].
The VPN attachment and Transit Gateway sit in the Network services account outside the three drawn VPC rectangles.

Each workload account contains an Internal API [Software system boundary]. Inside each boundary are two containers: the environment's private REST API, labeled Resource policy protected [Container: Amazon API Gateway], and the environment's API backend, labeled Runtime: unspecified [Container: AWS Lambda]. Specifically, the three pairs are dev: private REST API and dev: API backend; test: private REST API and test: API backend; prod: private REST API and prod: API backend.

FLOW A: BLUE DASHED DNS PATH
A1: Representative dev integration caller -> Private Resolver inbound endpoint. Label: query [DNS 53]. The same label includes Reply: private endpoint IP; no separate return arrow is drawn.
A2: Private Resolver inbound endpoint -> Private Resolver outbound endpoint. Label: execute-api query [DNS 53].
A3: Private Resolver outbound endpoint -> Azure Firewall, by a dashed line turning left and downward. Label: outbound ruleset [DNS 53], *.execute-api.{region}.amazonaws.com -> {Route 53 inbound endpoint IPs}:53.
A4: Azure Firewall -> Azure VPN Gateway. Label: DNS routing [53].
A5: Azure VPN Gateway -> Site-to-Site VPN attachment across the cloud boundary. Label: DNS routing [53 / IPsec VPN]. Nearby text identifies IPsec site-to-site VPN.
A6: Site-to-Site VPN attachment -> Transit Gateway. Label: DNS routing [53].
A7: Transit Gateway -> AWS Network Firewall. Label: DNS routing [53 / IDPS].
A8: AWS Network Firewall -> Route 53 inbound endpoint, via a dashed route going right, upward between the VPC columns, and then left into the endpoint. Label: DNS routing [53].
A9: Route 53 inbound endpoint -> Private hosted zone, by a dashed route above the two nodes ending downward at the zone. Label: resolve [DNS]; endpoint private IP.
Thus the pictured DNS path ends at the hosted zone and the request label at A1 states the returned private endpoint IP. A separate DNS response path and a separate zone-to-interface-endpoint connection are not drawn.

The legend specifies that a/b/c selects dev/test/prod and that there is one environment per request. These are conditional environment alternatives, not a request fan-out to all three.

Numbers are independent per flow; a/b/c selects dev/test/prod (one environment per request).
