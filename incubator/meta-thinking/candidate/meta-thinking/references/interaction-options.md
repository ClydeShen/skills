# Interaction options

Use the option that addresses the current obstacle.
Combine options only when each has a clear purpose.
Use these examples as a menu, not a checklist.

| Obstacle | Useful change | What would count as progress? |
| --- | --- | --- |
| The goal is unclear | Compare two concrete outcomes; ask what attracts or excludes each | A preference, constraint, or trade-off becomes clearer |
| Revisions keep changing surface details | Examine the objective, audience, or success criterion | A changed criterion leads to a different action |
| A convention is treated as a requirement | Separate facts, constraints, and assumptions; reconstruct from necessary conditions | An assumption can be tested or removed |
| Local fixes create problems elsewhere | Examine dependencies and competing objectives | A system constraint changes the proposed fix |
| A decision depends on an unknown fact | Retrieve evidence or run a small test | The result distinguishes between plausible choices |
| One answer seems inevitable | Seek a counterexample, alternative framing, or failure scenario | A credible alternative or boundary is identified |
| Critiques repeat without resolving anything | Verify the disputed claim with evidence, execution, or a specific condition | A criticism is supported, rejected, or left explicitly unresolved |
| A creative task has fast, observable feedback | Generate a small sample and iterate | The user can select a useful direction cheaply |
| An agent design grows extra roles | Identify the work and feedback each role adds | Each retained role addresses a distinct need |

For a reviewer skill, identify the target errors and available evidence before adding adversarial roles.
For a system prompt, express the goal and decision boundaries clearly.
For a workflow, assign work according to capabilities and feedback needs.
Keep human approval separate from evidence of correctness.
Keep tentative critiques separate from verified findings.

Example: repeated copy edits may reflect an undecided audience.
Compare short versions for two audiences to test that explanation.
If the real problem is missing product facts, retrieve those facts instead.

Name a philosophical or design principle only when it explains the actual change.
Use a different framing when the evidence does not support the initial explanation.
