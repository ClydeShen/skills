# Meta Thinking 指南

Meta Thinking 帮助人和 AI 在关键困惑中审视目标、假设、判断依据与互动方式，再选择一个更有希望的行动。它适合低频、按需使用：解决持续停滞、探索尚未成形的意图，或为 agent 行为选择合适的设计机制。

核心判断是：**当前哪个目标、假设或互动方式值得改变，怎样用一个小尝试检验它？** 向上审视的深度，以能改变下一步为度；恢复进展后回到任务。思考与记录都占用资源。

- **研究支持**：一手研究提供的相关机制和适用限制。原始来源、阅读范围及反例保留在研究记录。

本文可为 skill、system prompt、协作流程和记忆设计提供依据。固定层级、完整哲学分类及通用最优路由算法尚未得到验证。

## 适用边界

已确认方向：通常在用户显式请求，或互动出现值得检查的信号时使用。用户目标清楚、任务持续推进时，正常完成任务即可。

| 情境 | 值得关注的现象 | 有价值的结果 |
| --- | --- | --- |
| 互动停滞 | 相同障碍不断回来，修改没有带来新证据或可用进展 | 找到可检验的原因假设，并尝试不同路径 |
| 意图探索 | 用户还无法确定在意什么，或候选目标有冲突 | 形成更清楚的取舍和下一步 |
| agent 设计 | 要写 skill、system prompt 或 agentic workflow | 任务条件能解释所选的推理、分工和反馈机制 |

轮数、否定次数、目标变化和讨论长度只能提供线索。研究表明，偏好有时在表达和比较中形成；用户不断调整方向，可能是在获得理解。[R3]

综合建议：检查交流是否增加了相关事实、约束、取舍或可行动的理解。新的措辞本身不能证明有进展；新的反例即使没有立即产出方案，也可能构成进展。具体判断阈值需要案例验证。

## 从哲学审视到行动

这里的哲学层面，是审视“什么值得追求”“什么被当作事实”“什么算作证据”“为什么这样分配判断和行动”。这些问题可改变方案空间、验收标准或下一步动作。理论名称的作用是帮助解释机制。

以下关系是知识索引，不是必须逐项经过的流程。

| 需要审视的问题 | 已研究的依据 | 可以影响什么 |
| --- | --- | --- |
| 再多想一步是否值得？ | Rational metareasoning、resource-rational analysis [R1] | 选择查询、试验或直接行动；控制时间与停止条件 |
| 用户的目标是否已经形成？ | Preference construction [R3] | 通过具体比较形成取舍，允许目标修订 |
| 原问题是否遮住了关键关系？ | Step-Back Prompting 的局部实验 [R2] | 提取相关原则，再回到原约束求解 |
| 谁应该处理哪个环节？ | 自动化功能与程度、mixed-initiative [R1] | 证据收集、分析、决定和执行的分工 |
| 这次批评凭什么成立？ | 自我纠错的正反结果、工具反馈 [R2] | 区分提出质疑、核验质疑与修改答案 |
| 哪些经验值得再次使用？ | Episodic memory、反思与长期记忆评估 [R4] | 保存情境和结果，修正过期或冲突的概括 |

原稿中的 First Principles、Holism 等仍可作为研究线索；目前未建立它们到全部互动方式的可靠映射。遇到具体问题时，可以定向补查相关理论及其反例。

## 轻量干预的原则

综合建议：从交流中的具体事实形成一个暂时诊断，并提出足以检验它的改变。这个改变可能是一个关键问题、一组对比、一次查证，或一个可逆试验。帮助的质量取决于是否推动问题，不取决于用了多少概念。

例如，用户反复修改文案但始终不满意，而记录中受众尚未明确，可以比较面向两类受众的短版本。这同时检验“受众未定是否造成停滞”。它不是对所有反复修改的通用诊断。

停滞的原因应覆盖整段互动：用户目标、agent 的理解与回答、可用证据、工具和环境。缺事实时查证可能更有用；约束冲突时需要取舍；agent 反复给出相同答案时，应先改变其行为。不能默认把失败归为用户的思维缺陷。

若新行动恢复了进展，元层面的讨论可以结束。若没有改善，就修正诊断。已满足关键约束、继续查询不太可能改变选择、达到预算，或出现更便宜的可逆试验，都是候选停止理由，须结合情境判断。[R1]

研究支持：认知干预可能改善某些决策，同时增加主观负担；因此少步骤还应落实为较少的无效提问、合理耗时及可接受的用户投入。[R3]

## 为 agent 行为选择机制

已确认方向：显式请求设计 skill、system prompt 或 agentic workflow，是独立于停滞诊断的入口。此时可以从目标与任务结构出发，无需先寻找失败记录。

综合建议：设计应能解释任务条件如何影响机制选择。例如，路径可预定义且标准稳定时，明确流程可能足够；下一步依赖环境反馈时，动态选择更有理由；需要评价改进时，应先知道反馈依据是什么。[R3]

| 设计对象 | 推理应落实到的内容 |
| --- | --- |
| Skill | 适用情境、必要判断、所需证据及完成条件 |
| System prompt | 持续遵守的目标、决策原则与主动介入边界 |
| Agentic workflow | 环节之间的分工、反馈、交接和停止条件 |

例如 reviewer 的设计，需要知道目标错误类型和可用证据，再决定采用确定性检查、探索性批评或工具核验。增加一个 Critic 角色本身不会保证检错有效。[R2]

分工、推理操作和控制权限可以同时描述一个实例：AI 搜集证据，人和 AI 共同质疑方案，人作决定，AI 执行。因此 Centaur、Critic 和 Human Checkpoint 可以组合。当前不把它们设为互斥选项，也不固定概念层数。[R1]

## 用户画像与事件经验

已确认方向：在用户目录持久保存结构化用户画像，记录观察到的思考与协作模式、停滞原因及突破经验。维护采用 be lazy：重要停滞或突破发生时，才考虑更新。

综合建议：画像以可追溯、带情境的经验支持未来判断。例如：“在目标模糊的设计讨论中，比较具体候选曾帮助明确取舍。”这条经验说明了适用情境与有效改变，也保留了被反例修正的空间。[R4]

一条有用经验通常能回答：当时是什么情境，观察到了什么，尝试改变什么，后来发生什么，以及原因解释有多确定。时间、证据出处和反例有助于后续修正。这些是信息需求，不是已经确定的字段表或必填 schema。

观察、原因假设和有证据支持的解释，应在记录含义上区分。“换视角后有进展”先说明事件顺序；同时增加的事实或修改的约束也可能解释结果。一次突破不足以确定唯一 root cause。这里的根因研究以找到可改变的原因解释为目标，允许多因和不确定性。[R4]

重要事件可以触发“考虑写入”，不必每次写。存在新经验、反例或适用范围变化时，更新才有复用价值；已有相同记录时可以补证据或修正，信息不足时可以保留未知。模式使用也应考虑当前情境，相关证据缺失时不作个性化断言。

只记停滞和突破会得到选择性样本。记录里某种障碍反复出现，不能据此计算用户平时的思维模式频率。用户画像应帮助检索有用经验，而不是将特殊事件误读为普遍习惯。[R4，综合推断]

具体路径、格式、容量和跨会话可用性应在选定宿主后验证；结构化文件本身不保证准确记忆或有效个性化。

## 简洁性与激活边界

已确认方向：实际使用应保持低频、少操作步骤。知识深度可以通过按需参考提供，无需把本文内容全部写成运行时检查清单。

综合建议：主体保留适用判断、改变下一步的原则和停止边界；只有需要某个模式或经验时才取用相关材料。对外通常只需交代关键观察、建议改变及理由。

Agent Skills 文档描述了简短目录、激活后正文、按需资源的加载方式。隐式触发所需的线索要在激活前可见；只藏在正文内无法保证被发现。显式调用与自然触发应分别验证。具体客户端的能力与规则仍需实施时核对。[R3]

## 收敛判断与待验证问题

2026-10-25，基于用户授权，本次建议结束广泛发散，进入知识综合。已有来源覆盖成本、抽象、反馈、分工、目标形成、记忆及轻量交互。尚缺的主要是具体任务中的效果证据；更多概念不会直接回答这些问题。

这一收敛建议的信心为中，3.0：Owner 1（明确授权按判断收敛）、Research 0.5（已有相关来源，无完整方法实证）、Reasoning 1、Project history 0.5（已有研究与需求，无实际试用）。它不是产品成功概率。

| 未解决问题 | 下一步需要什么 | 何时值得补研究 |
| --- | --- | --- |
| 隐式触发是否准确？ | 同时包含顺利推进、正常探索与真实停滞的对话 | 误触发或漏触发有稳定类别时 |
| 干预是否带来净收益？ | 与原有互动比较质量、耗时和用户负担 | 某种干预反复无效且原因不明时 |
| 设计出的 agent 是否更好？ | 检查设计依据，再在目标任务上比较行为 | 缺少适用设计模式或可靠反馈时 |
| 画像是否帮助下一次互动？ | 比较无画像与有相关经验的表现，包含过期、冲突和无关记录 | 出现错误迁移、归因失真或检索问题时 |
| 用户是否逐渐提升思考能力？ | 长期观察能否在新问题中自主应用经验 | 短期效率提高但长期依赖或学习效果不清时 |

上表是后续评估的知识依据；首批案例、指标阈值和实验安排属于具体孵化项目。低频触发的价值、长期学习收益和画像的净收益均未验证。
